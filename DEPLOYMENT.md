# Deployment

Independent student prototype. **Not a Razorpay product. Not production-ready** merely because a public URL exists.

This document describes the **first public cloud deployment**:

- Backend: Render (Docker FastAPI)
- Database: Render Postgres
- Frontend: Vercel (Next.js)
- Events: in-process bus + transactional outbox **inside the API process**
- Graph: NetworkX (in-memory, rebuilt from SQL on boot)
- Investigator: deterministic fallback unless a hosted LLM is configured server-side

Local Docker Compose (Postgres, Redis, Neo4j, Kafka, Ollama) remains the lab stack. Do not treat `localhost` as a production URL.

## Architecture

```
Vercel (Next.js)
    REST + WebSocket
Render FastAPI (Docker, $PORT)
    Render Postgres
    in-process EventBus + outbox worker
    NetworkX graph
    xgb-iforest-v1-calibrated
```

**Not deployed on Render in this phase**

| Component | Why |
| --- | --- |
| Kafka | Optional local transport. Verified on a single lab broker only. No Render Kafka resource. |
| Dedicated worker | Outbox poller already runs in the API when `OUTBOX_BACKGROUND_WORKER=true`. Kafka consumer process is not required for `EVENT_BUS=inprocess`. |
| Redis / Key Value | WebSocket fan-out falls back to in-process memory. Single web instance is enough for the demo. |
| Neo4j | Render does not provide managed Neo4j. NetworkX is sufficient for the public demo. Local Neo4j config is unchanged. |
| Ollama | Do not run Ollama on Render. Use `LLM_PROVIDER=none` (fallback) or a hosted provider via server-side env vars. |

Alembic’s initial revision is `create_all`. The API calls `init_db()` on startup, so **no `preDeployCommand` migration** is required for this prototype.

## Render

Blueprint: root `render.yaml`.

Resources created:

- Web service `razorguard-x-api` (Docker, `backend/Dockerfile`, context `.`)
- Postgres `razorguard-x-db` (PostgreSQL 16)

Start command (binds Render `$PORT`):

```bash
uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}
```

Health check: `GET /api/v1/health`

### Create the Blueprint

1. Push `main` to https://github.com/ayushipandey252008/Razorguard-x-
2. Open [Render Dashboard → New → Blueprint](https://dashboard.render.com/select-repo?type=blueprint)
3. Connect the GitHub repo, branch `main`
4. When prompted (`sync: false` variables), set:
   - `SEED_ADMIN_PASSWORD` — **must not** be `prototype-pass` (`ENVIRONMENT=production` refuses that lab password)
   - `CORS_ORIGINS` — the Vercel origin, e.g. `https://your-app.vercel.app` (no trailing slash)
5. Apply the Blueprint and wait until the service is Live

`SECRET_KEY` is generated by Render (`generateValue`). Do not paste it into git or chat.

### After the first deploy

Record the public API URL, e.g. `https://razorguard-x-api.onrender.com`.

Verify:

```bash
curl -sS https://<render-host>/api/v1/health
```

Expect `status=ok`, `model_ready=true`, `model_version=xgb-iforest-v1-calibrated`, `event_bus.active=inprocess`, `graph_backend=networkx`, `llm.provider=deterministic_fallback`.

## Vercel

Root directory: `frontend`.

Framework: Next.js 14 (`npm run build` / `next start` handled by Vercel).

Browser-safe variables only:

| Name | Example |
| --- | --- |
| `NEXT_PUBLIC_API_URL` | `https://<render-host>` (no trailing slash) |
| `NEXT_PUBLIC_WS_URL` | `wss://<render-host>` |

Never put `SECRET_KEY`, database URLs, LLM keys, Neo4j, or Kafka credentials in `NEXT_PUBLIC_*`.

### Deploy

```bash
cd frontend
vercel login
vercel link
vercel env add NEXT_PUBLIC_API_URL production
vercel env add NEXT_PUBLIC_WS_URL production
vercel --prod
```

Or: Vercel Dashboard → Import GitHub repo → set Root Directory to `frontend` → add the two env vars → Deploy.

Then set Render `CORS_ORIGINS` to the exact Vercel origin (`https://…`, no path) and redeploy the API if it does not pick up the env change automatically.

## LLM

- Default cloud: `LLM_PROVIDER=none` → deterministic investigator (no cloud GPU, no Ollama).
- Hosted provider: set `LLM_PROVIDER`, `LLM_MODEL`, `LLM_BASE_URL`, `LLM_API_KEY` on **Render only**.
- **Do not run Ollama on Render.**

### Optional demo-only local LLM bridge

If you temporarily need the Mac Ollama process during a live demo:

```
local Ollama (127.0.0.1:11434)
  → authenticated ngrok tunnel
  → Render LLM_BASE_URL + LLM_PROVIDER=openai + dummy LLM_API_KEY
```

This is **not** production architecture. Do not tunnel the Render API through ngrok. Do not commit ngrok credentials.

## Neo4j

Public demo uses NetworkX. To point a cloud API at an external Neo4j later (Aura or self-hosted), set `GRAPH_BACKEND=neo4j` plus `NEO4J_URI` / `NEO4J_USERNAME` / `NEO4J_PASSWORD` on Render only. Do not invent a Render Neo4j resource.

## Kafka

Public demo uses `EVENT_BUS=inprocess`. Outbox rows are still written and drained in-process. Do not claim Kafka is running in production unless an external broker is configured **and** verified.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| API crash on boot: production seed password | `SEED_ADMIN_PASSWORD` must be set and must not be `prototype-pass` |
| API crash: SECRET_KEY | must be ≥32 chars and not a documented placeholder |
| Health 502 / spin-up delay | Starter instances may cold-start; retry after ~30–60s |
| Browser CORS errors | `CORS_ORIGINS` must match the Vercel origin exactly (scheme + host, no slash) |
| Login works locally, fails on Vercel | `NEXT_PUBLIC_API_URL` baked at **build** time; rebuild after changing it |
| Live wire silent | `NEXT_PUBLIC_WS_URL` must be `wss://` to the same Render host; production WebSocket requires a JWT query token |
| Empty graph after restart | Expected for NetworkX: rebuilt from SQL on boot |
| Model retrained on boot | Live artifacts missing from the image; `ml/models/` must be in the Docker build context |

## Security notes

- JWT HS256, RBAC, rate limits, audit logs, redaction — lab controls, not a bank-grade control plane
- `ENVIRONMENT=production` refuses placeholder JWT secrets and the documented lab seed password
- CORS is an allow-list, not `*`
- No real card data
- Do not commit `.env`
